# Physical acceptance — execute on the prototype, record the results

No physical tests in this document have been performed. The software build and static checks are complete. Keep the torch trigger and VFD run circuits disconnected until the logic, stop chain and motion tests pass. Use a meter/logic analyzer and an unloaded mechanism first.

1. **Identity and power.** Verify the silk-screen says Kraken V1.1, the MCU is STM32H723, and S1–S4 sense resistors match the V1.1 0.050-ohm documentation. Verify the separate board/DC and motor power arrangements from BTT's manual. Confirm actual DC polarity, fusing and protective earth. Remove DIAG endstop jumpers for the four physical switches. Keep S5–S8 unwired.
2. **Bootloader and image.** Back up the original firmware/configuration. Use BTT's documented 128 KiB bootloader update route for this board, with the supplied engineering BIN. Verify the image hash against `verification.json`. Do not write this application image at flash address zero or overwrite the bootloader. USB enumeration, a usable grblHAL greeting, the expected board name, and stable repeated resets must pass before proceeding.
3. **Read the controller.** Save `$I`, `$$`, `$PINS` and the Trinamic diagnostic report. Verify four motor channels, independent Y2, no SPI initialization fault, Rsense=50 mOhm, 16 microsteps, and 500 mA RMS commissioning current. Check the actual enable and chip-select lines. S5–S8 must remain disabled and deselected. Measure driver/motor current according to the driver and motor documentation; a DC supply current reading is not phase RMS current.
4. **Inputs and stop chain.** Check every switch independently in status/pin reports before motion. Verify X/Y1/Y2/Z switches cannot be confused. Open each NC circuit and disconnect each connector to verify the intended fault indication. Establish inversion/pull-up settings from the actual interface. Operate E-stop/breakaway with the USB host disconnected and verify tool permission is removed by hardware. Check reset, bootloader mode and board-power loss leave the isolated tool output off.
5. **Scale and direction.** Confirm the selected modules really have 10 mm/rev X/Y screws and 5 mm/rev Z screw, with 1.8-degree motors. The compiled assumptions are X/Y=320 steps/mm and Z=640 at 16 microsteps. If the mechanical lead differs, correct it before motion. Jog only 1 mm at first, verifying direction, displacement and both Y motors. Determine `$3` and the ganged-direction inversion from actual motor mounting. Never determine direction by homing a fully assembled gantry at speed.
6. **Dual-Y home.** Square the gantry mechanically first. Enable homing only after switch polarity/direction are verified. With tool power inhibited, home at low speed and trigger Y1 and Y2 separately; the corresponding motor must stop while the other finishes within the 2.5 mm configured difference limit. Trigger only one switch as a deliberate fault and confirm the homing mismatch alarm before excessive racking. Set squaring offset from measured diagonals. The 2.5 mm value is an initial protective limit, not proven structural tolerance.
7. **Travel and motion.** Test soft/hard limits at low energy, measure actual travel margins, then set them to the measured usable envelope. Increase velocity/acceleration only after no-stall and load tests. Compile defaults are just 600 mm/min X/Y, 300 mm/min Z, and 20/20/10 mm/s² acceleration; these are not plasma cutting speeds. Choose motor RMS current from verified motor data and temperature tests before any loaded cutting qualification.
8. **Router interface.** Set `$350=0`, cold-reset, and verify the report says PLASMA Off. With VFD run disconnected, meter the isolated 0–10 V converter at `M3 S12000` and `M3 S24000`: expected calibrated speed requests are 5 V and 10 V. `M5`, reset, E-stop, broken interface power and disconnected USB must be tested against the final interface's intended behavior. Confirm only the router can be selected by the keyed circuit. Connect the VFD interface only after its documented terminal functions match; test rotation/cooling at appropriate supported speed without a cutter installed.
9. **Simulated plasma signals.** Confirm `$PINS` maps PD12/PD13/PD14 to the intended logical aux ports. Set `$367=0`, `$368=1`, `$369=2` only if that mapping is verified. Set `$360=1` (one start attempt), `$674=2` (sync Z after THC), and `$350=2`, then cold-reset. Verify the controller reports PLASMA Up/down with no 'mode changed' or 'failed to initialize' warning. Keep torch trigger disconnected. Simulate Arc OK and UP/DOWN from the actual isolated interface. During a slow XY line, measure Z pulses and motion in the proper direction, timing after THC delay, velocity anti-dive during deceleration, and Z position after THC ends. Verify each of no Arc OK, lost Arc OK, both UP and DOWN, stuck input, input unplugged, E-stop and breakaway stops/holds as intended; do not presume software behavior from a compile.
10. **Cutter integration and cutting.** Only the exact cutter/THC combination with a documented isolated CNC interface can proceed to this step. Verify the manual's torch trigger and arc-sensing connection with the interface supplier. Do not infer HF compatibility from 'pilot arc' or an AG60-style torch. Commission without automatic retries; validate pierce height/delay, cut height, THC response and stop behavior on scrap at supported cutting speed. Run repeated starts while observing USB resets, input false triggers, lost steps and EMI. A failed test blocks live cutting until corrected.

## Operational mode change after acceptance

Stop the job, `M5`, inhibit tool power, move to the defined safe tool-change position, change the bed/head and hardware mode selector, select `$350=0` for router or `$350=2` for plasma, and cold-reset the motion controller. Read back the active mode and input health before restoring tool permission. Re-home if machine position or power was lost; re-probe the selected bed/workpiece. No firmware reflash is required for ordinary mode swaps.

The two control settings profiles are intentionally not auto-sent: limit polarity, homing direction and aux-port mapping depend on the physical harness and must first be measured. A CB1/SBC may be a USB G-code host; this motion image runs on Kraken itself and does not run Klipper.
